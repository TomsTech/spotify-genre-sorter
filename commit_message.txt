🛡️ Sentinel: [Low] Fix XSS in Rate Limit Banner via innerHTML

🎯 What: Fixed a potential DOM-based Cross-Site Scripting (XSS) vulnerability in the rate limit banner. The `title` and `msg` variables were being directly concatenated into `banner.innerHTML` without sanitization.

⚠️ Risk: While the current implementation computes `maxPct` safely as a number, injecting raw string variables into `innerHTML` is an insecure pattern. If the data objects computing these strings were ever populated with unvalidated user input or attacker-controlled API payloads, it could lead to arbitrary JavaScript execution in the context of the user's session.

🛡️ Solution: Wrapped the `title` and `msg` variables in the existing `escapeHtml()` function before interpolating them into the HTML string, effectively mitigating the XSS risk by encoding dangerous characters.
